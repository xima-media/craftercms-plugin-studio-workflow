CrafterCMS Studio Plugin

Redaktionelle Abläufe im Studio steuern

Crafter Workflow legt ein Kanban-Board, Kommentare, Aufgaben und einen Papierkorb direkt in CrafterCMS Studio. Dieser Guide zeigt, was die einzelnen Funktionen tun, wo sie zu finden sind und wie sie zusammenspielen.

org.rd.plugin.crafterwf CrafterCMS 4.0 bis 4.4 nur Authoring, kein Delivery

Was das Plugin macht

CrafterCMS bringt von Haus aus Publishing und einen Review-Schritt mit, aber keinen Ort, an dem eine Redaktion sieht, woran gerade wer arbeitet. Genau diese Lücke füllt das Plugin. Es ersetzt das Publishing von CrafterCMS nicht, es legt sich als Koordinationsschicht darüber.

Vier Begriffe genügen für den Anfang:

BegriffBedeutung
Workflow Ein benannter Ablauf, sichtbar als ein Board. Eine Site kann mehrere haben, etwa „Redaktion“ und „Kampagnen“.
Schritt Eine Spalte des Boards, zum Beispiel Backlog, In Progress, Review, Done. Die Reihenfolge und die erlaubten Übergänge legt ein Administrator fest.
Paket Die Karte auf dem Board und die eigentliche Arbeitseinheit. Ein Paket steht immer in genau einem Schritt.
Anhang Eine Seite, eine Komponente, ein Asset oder ein externer Link, der an einem Paket hängt. Über Anhänge greift das Paket auf echte Inhalte zu.

Rund um diesen Kern liegen Funktionen, die auch ohne Board nutzbar sind: Kommentare an einzelnen Seiten, persönliche Aufgaben, ein Kalender, Benachrichtigungen, ein Papierkorb und ein Audit-Log.

Wichtig zu wissen

Ein Inhalt in einem Paket ist deshalb noch nicht veröffentlicht. Live steht weiterhin nur, was über das reguläre Publishing von CrafterCMS gegangen ist. Das Board zeigt den redaktionellen Stand, nicht den Auslieferungsstand.

Wo alles liegt

Das Plugin verteilt sich auf drei Stellen der Studio-Oberfläche. Diese Tabelle ist die Antwort auf die häufigste Frage überhaupt.

OrtWas dort liegt
Linke Werkzeugleiste
Tools-Panel		 Der Eintrag Workflow öffnet das Board. Gibt es nur einen Workflow, trägt der Eintrag dessen Namen. Bei mehreren klappt eine Liste auf.
Vorschau-Werkzeugleiste
oben rechts		 Page packages, Content comments, Notifications, Tasks, Calendar und Recycle bin. Alle beziehen sich auf die gerade geöffnete Seite oder auf den angemeldeten Benutzer.
Project Tools
Crafter Workflow		 Die Administration: General für die Datenbank, Workflows für den Flow-Editor, Audit Log für die Historie.

Der Papierkorb-Button erscheint nur bei Schreibrechten auf /recyclebin. Fehlt ein Icon, ist das in aller Regel eine Frage der Berechtigung, nicht der Installation.

In 10 Minuten startklar

Der kürzeste Weg von der frischen Installation zum ersten bewegten Paket. Schritt 1 und 2 macht ein Administrator einmalig.

  1. Datenbank anlegen Project Tools → Crafter Workflow → General → Install. Danach steht dort „Workflow Database: Installed“.
  2. Workflow anlegen Reiter Workflows → Create workflow. Ein Standard mit Backlog, In Progress und Done ist in Sekunden gebaut.
  3. Board öffnen Linke Werkzeugleiste → Workflow.
  4. Erstes Paket anlegen In der ersten Spalte auf Add package, Titel vergeben.
  5. Inhalt anhängen Auf der Karte das Drei-Punkte-Menü öffnen, Existing Content wählen und eine vorhandene Seite verknüpfen.
  6. Paket bewegen Die Karte in die nächste Spalte ziehen. Im Audit-Log steht danach der Übergang.

Das Board

Ort Linke Werkzeugleiste → Workflow

Was hier geht

  • Paket anlegen über Add package am Fuß der Spalte. Der Link erscheint nur in Spalten, die dafür freigegeben sind.
  • Paket ziehen von Spalte zu Spalte. Sind Übergänge definiert, sperren sich während des Ziehens alle Spalten, die nicht erlaubt sind.
  • Karte öffnen per Klick. Die Detailansicht zeigt Beschreibung, Fälligkeitsdatum, Anhänge, Kommentare, Aufgaben und die Historie des Pakets.

Wird ein Zug abgelehnt, liegt das an einer Regel des Zielschritts: entweder fehlt die nötige Rolle oder die angehängten Inhalte passen nicht zu den Vorgaben. Die Meldung nennt den Grund.

Pakete und Inhalte

Ort Board → Karte → Drei-Punkte-Menü

Ein Paket ohne Inhalt ist nur eine Notiz. Interessant wird es, sobald echte Seiten daran hängen, denn dann lassen sich die Studio-Aktionen direkt von der Karte aus auslösen.

MenüpunktWirkung
New PageLegt über den Studio-Dialog eine neue Seite an und hängt sie ans Paket.
New ComponentDasselbe für Komponenten unterhalb von /site/components.
Existing ContentSucht vorhandene Inhalte und hängt sie an.
Request ReviewStartet den Review von CrafterCMS für die angehängten Inhalte.
Reject SubmissionWeist eingereichte Inhalte zurück.
PublishVeröffentlicht die angehängten Inhalte.
Archive PackageSchließt das Paket ab. Es verschwindet vom Board, die Historie bleibt.

Die drei mittleren Punkte tauchen nur auf, wenn wenigstens ein Anhang im passenden Zustand ist. Dahinter stecken die normalen Studio-Dialoge, es gilt also unverändert, was auch ohne Plugin gilt: Berechtigungen, Terminierung, Abhängigkeiten und die Standard-Mails von CrafterCMS.

Ein Inhalt, mehrere Pakete

Der Button Page packages in der Vorschau-Werkzeugleiste dreht die Blickrichtung um: Er zeigt für die gerade geöffnete Seite alle Pakete, in denen sie steckt, und erlaubt es, direkt ein neues zu starten.

Kommentare

Ort Vorschau-Werkzeugleiste → Content comments, außerdem in jeder Paket-Karte

Kommentare gibt es an zwei Arten von Zielen: an einem Paket und an einem konkreten Inhalt. Beide sind unabhängig voneinander, ein Inhalt braucht also kein Paket, um kommentiert zu werden.

  • @mention im Text schlägt Benutzer vor und benachrichtigt die Genannten.
  • Resolve markiert einen Punkt als erledigt, Archive blendet ihn aus. Beides ist umkehrbar.
  • Kommentare an einem Paket merken sich, in welchem Schritt sie entstanden sind.

Aufgaben und Kalender

Ort Vorschau-Werkzeugleiste → Tasks und Calendar

Aufgaben sind bewusst eigenständig. Sie können an einem Paket oder an einem Inhalt hängen, müssen es aber nicht. Eine reine Merkliste ist damit genauso möglich wie eine eng an den Workflow gekoppelte Arbeitsteilung.

Das Icon in der Werkzeugleiste trägt die Zahl der offenen Aufgaben und färbt sich rot, sobald etwas überfällig ist.

Benachrichtigungen

Ort Vorschau-Werkzeugleiste → Notifications

Ausgelöst wird eine Benachrichtigung heute in drei Fällen:

  • Eine Aufgabe wird zugewiesen, geändert, abgeschlossen oder archiviert. Empfänger ist der Bearbeiter, nie der Auslöser selbst.
  • Jemand wird in einem Kommentar per @name erwähnt.
  • Jemand veröffentlicht am Workflow vorbei, siehe Umgehungs-Schutz. Dann werden die Beteiligten des Pakets und die Administratoren informiert.
Voraussetzung für E-Mail

Drei Dinge müssen zusammenkommen: SMTP ist in Studio konfiguriert, der Empfänger hat eine E-Mail-Adresse im Benutzerprofil, und er hat den Schalter im Panel aktiviert. Fehlt eines davon, bleibt es bei der Meldung in der Oberfläche.

Papierkorb

Ort Vorschau-Werkzeugleiste → Recycle bin

Gelöscht wird hier nichts. Der Inhalt wandert im Site-Repository nach /recyclebin/{uuid}/… und lässt sich von dort zurückholen. Das Menü des Buttons bietet drei Wege:

  • Aktuelle Seite weglegen, mit Rückfrage.
  • Mehrere Elemente auswählen über Suche und letzte Aktivitäten.
  • Papierkorb öffnen für Filter, Sortierung, Vorschau, Wiederherstellung und endgültiges Löschen.

Existiert der ursprüngliche Pfad beim Wiederherstellen schon wieder, fragt das Plugin nach, bevor es überschreibt. Hing der Inhalt an einem Paket, wird die Verknüpfung beim Weglegen entfernt.

Workflow bauen

Ort Project Tools → Crafter Workflow → Workflows → Edit workflow

Die Zeichenfläche

  • Schritte ziehen ordnet das Diagramm. Die Position wird mitgespeichert und ist reine Darstellung.
  • Blaue Punkte verbinden zieht einen Move-Pfeil. Er legt fest, wohin ein Paket aus diesem Schritt gezogen werden darf.
  • Add step hängt einen Schritt an. Ausgewählt lassen sich darunter Name, Farbe und Regeln bearbeiten.
  • Align row ordnet alles in eine Reihe, Backward arrows blendet Rückwege ein.
Merke

Solange ein Schritt keinen einzigen Move-Pfeil hat, darf von dort in jede Spalte gezogen werden. Erst der erste Pfeil schaltet die Beschränkung scharf. Das ist der häufigste Stolperstein beim ersten eigenen Workflow.

Was ein Schritt kann

EinstellungBedeutung
Name und FarbeTitel und Farbkante der Spalte auf dem Board.
Pakete anlegen erlaubtBlendet Add package in dieser Spalte ein.
Rollen-RegelWer ein Paket hierher bewegen darf: alle, nur bestimmte Rollen oder alle außer bestimmten.
Inhalts-RegelBedingungen an die Anhänge, etwa Pfadmuster oder Content-Types. Wahlweise müssen alle oder nur ein Anhang passen.
AktionWas automatisch passiert, sobald ein Paket einläuft. Siehe Automatik.
TerminalKennzeichnet eine Abschluss-Spalte. Aktuell nur eine Notiz ohne Wirkung auf das Verhalten.

Gespeichert wird der Workflow als Datei im Site-Repository unter /config/studio/workflow/definitions/. Er ist damit versioniert und lässt sich wie jede andere Konfiguration zwischen Umgebungen übertragen. Die laufenden Pakete stehen dagegen in der Datenbank.

Automatik

Zwei Mechanismen nehmen der Redaktion Handgriffe ab. Beide sind optional, ein Workflow funktioniert auch vollständig manuell.

Aktion beim Einlaufen in einen Schritt

Ein Schritt kann eine Aktion tragen, die ausgelöst wird, sobald ein Paket dort ankommt. Ausgeführt wird sie im Namen der Person, die das Paket bewegt hat, mit deren Berechtigungen.

AktionWirkung
Review anfordern
Staging oder Live		Reicht die Anhänge zur Freigabe ein.
Veröffentlichen
Staging oder Live		Veröffentlicht die Anhänge direkt.
Paket archivierenSchließt das Paket ab und nimmt es vom Board.

Für die Veröffentlichungs-Aktionen lässt sich ein Folgeschritt hinterlegen, in den das Paket bei Erfolg weiterwandert. Schlägt die Aktion fehl, etwa weil keine Anhänge da sind oder Staging nicht aktiv ist, kann das Paket zurückspringen, und der Benutzer sieht die Fehlermeldung von CrafterCMS.

Pakete automatisch anlegen

Im Reiter Content event listeners eines Workflows lassen sich Regeln hinterlegen, die beim Anlegen oder Speichern von Inhalten greifen. Eine Regel besteht aus einem optionalen Content-Type, einem optionalen Pfadmuster, einem Titel-Präfix und einem Zielschritt.

Passt ein gespeicherter Inhalt, sucht das Plugin ein aktives Paket, das ihn bereits enthält. Findet es keines, legt es eines im Zielschritt an und hängt den Inhalt an. Liegt das Paket in einem anderen Schritt, wird es in den Zielschritt verschoben.

Nur mit Zusatzinstallation

Diese Automatik greift auf einen Haken tief in der Studio-Installation zu und ist als einzige Funktion des Plugins nicht mit der reinen Plugin-Installation abgedeckt. Alles andere in diesem Guide läuft ohne den Zusatzschritt.

Umgehungs-Schutz

Sobald ein Workflow mindestens einen Schritt mit Veröffentlichungs-Aktion hat, achtet das Plugin darauf, dass niemand am Ablauf vorbei publiziert. Greift ein Benutzer in Studio zu Publish, Request Publish oder Reject, während der Inhalt in einem Paket außerhalb dieser Schritte liegt, meldet sich der Schutz.

EinstellungVerhalten
Blockieren
Standard		 Der Studio-Dialog schließt sich, ein Hinweis erklärt, dass zuerst der passende Schritt erreicht werden muss. Die Aktion wird abgebrochen.
Bestätigen lassen Der Benutzer muss eine Warnung ausdrücklich bestätigen und kann dann fortfahren. Bestätigung und Aktion landen im Audit-Log, die Beteiligten werden benachrichtigt.

Eingestellt wird das pro Workflow, zusammen mit einem optionalen eigenen Warntext.

Reichweite

Der Schutz wirkt in der Studio-Oberfläche. Aufrufe direkt gegen die Studio-Schnittstelle gehen daran vorbei. Er ist ein Leitplanke für die tägliche Arbeit, keine technische Sperre.

Audit-Log

Ort Project Tools → Crafter Workflow → Audit Log

Eine durchsuchbare Liste dessen, was im Workflow passiert ist: wer, was, woran und wann. Filtern lässt sich nach Benutzer, Vorgang, Ziel und Zeitraum. Die Historie eines einzelnen Pakets steht außerdem unten in dessen Detailansicht.

VorgangWann er entsteht
package_createdPaket angelegt
package_step_changedPaket in einen anderen Schritt bewegt
package_modifiedTitel, Beschreibung, Termin, Anhänge geändert oder Paket archiviert
package_step_actionAutomatische Aktion eines Schritts gelaufen, erfolgreich oder nicht
task_created, task_modifiedAufgabe angelegt oder geändert
workflow_bypass_*Umgehung bestätigt oder durchgeführt
recycle_bin_item_*Inhalt weggelegt, wiederhergestellt oder endgültig gelöscht

Das Log ergänzt die Versionierung von CrafterCMS, es ersetzt sie nicht. Kommentare und Änderungen an Workflow-Definitionen werden derzeit nicht erfasst.

Grenzen

Was das Plugin bewusst nicht tut, ist genauso wichtig wie sein Funktionsumfang. Wer das vorab weiß, plant realistischer.

  • Keine Pflicht zur Teilnahme. Inhalte lassen sich weiterhin ganz ohne Paket bearbeiten und veröffentlichen.
  • Kein Status am Inhalt selbst. Der Fortschritt hängt am Paket, nicht an der einzelnen Seite. Eine Seite kann in mehreren Paketen liegen.
  • Keine serverseitige Sperre. Der Umgehungs-Schutz wirkt in der Oberfläche.
  • Keine Sperre von Inhalten und kein Vier-Augen-Zwang.
  • Keine eigenen Rechte. Es gelten die Rollen und Rechte von Studio. Wer die Site administrieren darf, darf auch Workflows ändern.
  • Nur Authoring. Auf der ausgelieferten Website ist vom Plugin nichts zu sehen.
